## Purpose
`AGENTS.md` is a machine-optimized context file placed in the project root by `initKnowledgeBase`. AI coding agents (Claude Code, Zed, Cursor, etc.) auto-load files named `AGENTS.md` or `CLAUDE.md` at session start, giving them project orientation before any user message. Its content is intentionally terse and structured for fast machine parsing — not for human reading.

## Decisions
- **Project root, not inside `.knowledge/`**: Agents auto-load files from the project root. Placing it inside `.knowledge/` would require an explicit tool call to discover it. Root placement gives zero-cost context injection before any tool use.
- **Pointers over content**: AGENTS.md does not duplicate knowledge — it points to `.knowledge/` and tells agents to call `read_knowledge_base` first. Duplication causes drift; pointers stay correct.
- **Verification commands inline**: The build/verify commands are repeated here from `conventions.md` so agents can run them without a separate read call. This is the one intentional duplication, justified by access frequency.
- **Generated by `init`, not `generate`**: `generate` produces knowledge files from source code via Claude. AGENTS.md is structural scaffolding — always the same shape, just parameterized by project name. It belongs with `init`.

## Patterns
Template structure (in order, no blank sections):

```markdown
# <project-name>

## Knowledge Base
This project uses knowledge-mcp. Read `.knowledge/` before writing code.
Start every session: call `read_knowledge_base` with no arguments.

## Build & Verify
<bullet list of commands from ## Verification in conventions.md, or placeholders>

## Purpose
<one sentence from architecture.md ## Purpose, or placeholder>

## Key Constraints
<bullet list of the 3–5 most critical constraints from architecture.md and conventions.md>
```

## Constraints
- `initKnowledgeBase` must not overwrite an existing `AGENTS.md`. Same idempotency rule as all other init files.
- `AGENTS.md` is written to `projectDir` directly (the project root), not inside `.knowledge/`.
- Do not use `writeKnowledgeFile` to write `AGENTS.md` — that function targets `.knowledge/`. Use `writeFile` directly to `join(projectDir, 'AGENTS.md')`.
- Content must stay under ~60 lines. Agents load this before any tool call; bloating it wastes context.
- When the `read_knowledge_base` MCP tool is called with no arguments, the handler appends AGENTS.md content to the response if the file exists. This is handled in `tools.ts`, not in `reader.ts` — AGENTS.md has no frontmatter and is not a `KnowledgeFile`.

## Interfaces
AGENTS.md is not a TypeScript interface — it is a file written by `initKnowledgeBase`. No exported function is specific to it; it is produced as part of the init file list.
